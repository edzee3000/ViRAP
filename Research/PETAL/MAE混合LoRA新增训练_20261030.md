# 新增MAE混合LoRA实验

这是独立新增的一次训练，不修改原来GPU0–7的8个实验。运行在trinity-2-23的GPU8，任务名`M1_LoRA_r8_b16_s17`，tmux `mae-hybrid-lora`。监控仍为本机转发地址 http://127.0.0.1:55318/ ，刷新即可看到第9个任务。

## 参数更新范围

|位置|原权重|新增适配|
|---|---|---|
|MAE第1–8层的QKV、输出投影、FFN两层|冻结|LoRA，r=8，alpha=16|
|Patch Embedding投影|冻结|卷积低秩残差，r=8，alpha=16|
|MAE第9–12层|全部训练|不再额外加LoRA|
|最终LayerNorm|训练|无|
|前8层内部LN、偏置、CLS、固定位置编码|冻结|这些向量不套矩阵LoRA|
|摄影CNN、风格读取、关系模块、空间/颜色模块|训练|沿用M1，K=4|

LoRA使用 `W x + (alpha/r) B A x`，A随机、B零初始化，初始不改变公开预训练编码器函数。前8层原矩阵仍冻结，但不能用no_grad包住其前向，否则适配器无法训练。新增单元测试确认梯度到达前8层LoRA和末4层原权重，而冻结基底无梯度。

## 实际参数

- 每个前层block新增：QKV24,576 + proj12,288 + fc1 30,720 + fc2 30,720 = 98,304。
- 8层合计786,432；Patch Embedding额外12,288。
- **LoRA新增总数798,720。**
- 总模型92,201,719参数；其中可训练34,756,087。
- 共享编码器参数只计算一份，输入/参考各执行一次。

预训练权重仍来自官方MAE预训练encoder，不使用PETAL权重/特征。LoRA按标准低秩适配公式实现，参考 https://github.com/microsoft/LoRA 。当前训练不做自动合并，不能宣称适配分支没有推理开销。

## 真正的batch=16

按内容/目标的**确切原比例输出尺寸**分桶，同尺寸16张一起前向反向。没有为了组batch把内容图拉成方形、随机裁剪或补边。参考图在GPU上按原编码器同样的bilinear+antialias路径缩为224后堆叠；编码器的224→224再次插值为恒等。

桶内不足16张的尾批保留，不丢样本，实际均值和完整批次比例写入config。名义batch16，物理microbatch16，梯度累积1。不是原训练“单图×16次累积”。

已经在该2080 Ti上，使用真实384×384的最大尺寸16张批次跑通3次前向、反向和优化。峰值4522.43MiB（约4.42GiB），未发生OOM，故正式训练使用物理16。

## 训练与对照边界

- K=4，seed17，4epoch；从开始即末4层/最终LN全量更新＋前部LoRA，不设原版的2epoch heads-only阶段。
- 新增模块初始LR2e-4，LoRA1e-4，末4层/最终LN1e-5；AdamW、warmup与cosine衰减、梯度裁剪1、FP16 GradScaler溢出恢复。
- 沿用59,100训练/400验证的源图隔离划分，训练长边384、原比例，固定验证与预览；不使用测试集选择模型。
- 同尺寸分桶每epoch全覆盖并随机打乱，保存分桶顺序哈希。不同于原batch8随机单图累积，因此这次同时改变适配、batch和优化顺序/阶段，不能把结果差异全部归因于LoRA。
- 本地原子断点、异常最多额外恢复2次、两小时恢复文件备份、结束归档，均独立于本机SSH连接。
