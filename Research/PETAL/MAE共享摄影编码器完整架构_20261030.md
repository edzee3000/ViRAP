# MAE共享摄影编码器：完整模型设计与精确参数

日期：2026-10-30。状态：M0/M1架构实例、参数、前向/损失/梯度验证；不是已训练完整模型。远端验证结果仅支持MAE作为冻结全局调色探针的强候选，不保证完整模型优势。

## 1. 两个明确版本

- M0（替换对照）：MAE-B/16 + 原光度分支/读取器/关系模块 + 参考条件空间模块，K=2。
- M1（推荐待验证）：同上，K=4。与M0仅局部分量数不同；不同时加入新融合、dense语义匹配和边缘细化。

M0为91,401,581参数，M1为91,402,999参数，差1,418。MAE视觉输入224、光度输入224，与此前D组探针保持一致；DINOv2 V2.1原先视觉280/光度256。因此严格说M0是MAE协议下的替换对照；需要研究骨干因素时，DINO版本也应使用同分辨率输入及同token读取预算，而不是把旧分辨率差异误认为骨干差异。

## 2. 总流程

```
输入照片 Ic ─┐                    ┌─ 16×256 tokens Sc、全局向量 zc
             ├─ 同一个摄影编码器 E ┤
参考照片 Ir ─┘                    └─ 16×256 tokens Sr、全局向量 zr
                                            ↓
                               有方向的 Pair Conditioner
                                            ↓
                                     z_pair：[B,256]
                                       /          \
                  条件颜色MLP→全局/局部LUT      输入坐标特征 + FiLM
                                       \          /
                                输入图原尺寸查表与局部融合
                                            ↓
                                       输出调色照片
```

只共享一份参数，输入/参考各执行一次。MAE只作为特征编码器；不使用75%随机mask、不添加mask token、不运行其预训练像素解码器。整个调色网络不使用diffusion，不从参考特征栅格直接复制像素。

## 4. 共享摄影编码器：89,199,616

### 4.1 MAE-B/16视觉骨干：85,798,656

|项|配置|
|---|---|
|图像|固定RGB mean/std归一化，224×224|
|Patch Embedding|Conv2d(3,768,kernel16,stride16)|
|Patch数量|14×14=196，加1个CLS|
|编码宽度|768|
|层数|12|
|注意力头|12，每头64维|
|FFN|768→3072→768，GELU|
|Block|Pre-LN，多头自注意力残差 + FFN残差|
|位置|197×768固定2D sin/cos，含CLS位置|
|读取|第4/8/12层，全部保持197×768|
|输出归一化|与已有探针一致，使用最终LayerNorm读取各层|

三层是同网格的不同深度特征，不是多分辨率金字塔。第4/8层不预先赋予“颜色层/语义层”等未经验证的解释。

|骨干子项|参数|

|Patch Embedding|590,592|

只加载官方MAE预训练encoder；严格丢弃decoder和mask_token，不使用ImageNet分类微调后的权重。源代码/权重来源：https://github.com/facebookresearch/mae 。部署不需要预训练重建解码器。

### 4.2 原始Lab摄影分支：314,624

固定RGB标准化不是逐图亮度归一化；Lab分支直接从原始[0,1]RGB计算，不使用逐图均值/方差归一化。

|层|操作，均3×3/stride2 + GELU|输出|参数|
|---|---|---|---:|
|1|3→32|32×112×112|896|
|2|32→64|64×56×56|18,496|
|3|64→128|128×28×28|73,856|
|4|128→192|192×14×14|221,376|

后三层各池化8×8并投影为256维，192个tokens。64/128/192→256的三组投影共99,072参数。

### 4.3 统计与视觉投影

- MAE三层各自Linear768→256：590,592参数，591个tokens。
- 亮度32维直方图、16×16色度联合分布、6亮度区间共30维统计、8维全局/局部矩，各Linear→256：84,480参数，4个tokens。
- 10种来源嵌入：2,560参数；不额外给读取器加XY位置，但MAE特征本身已含空间上下文。

### 4.4 风格读取与输出

Memory = 591视觉 +192摄影CNN +4统计 = **787×256**。

16个可学习查询（4,096参数），经过2层TransformerDecoder：d256、8头、FFN1024、dropout0、norm_first；每层包含查询自注意力、对memory的交叉注意力及FFN。两层共2,106,880参数。

输出LayerNorm：512参数。16个tokens的均值/标准差拼接512维，经LayerNorm→Linear512256→GELU→Linear256256：198,144参数。

每图输出全局256维和16×256 tokens。保持现有读取器以便继承探针证据；不宣称787-token混合已经解决模态不均衡，也不宣称输出是完全无内容的纯风格。

## 5. 有方向的关系模块：1,644,032

全局 `[zc,zr,zr-zc,zc*zr]`1024→512→256：656,128。

输入tokens做Q、参考tokens做K/V，256维8头交叉注意力，加FFN1024和3个LN：790,272。

更新前后token差汇聚，经Linear256256：65,792；与全局关系拼成512维，再Linear512256+GELU+LN：131,840。

输出256维z_pair。角色有方向，输入/参考不是可交换关系。这不是显式像素或语义区域对应。

## 6. 参考条件空间模块：407,780

|步骤|输出/操作|参数|
|---|---|---:|
|输入MAE空间投影|768×14×14 → Conv1×1至128 → 插值64×64|98,432|
|输入光度/原始特征|CNN64通道 + RGB/亮度/局部差/梯度6通道|0，复用已有特征|
|融合1|198→96 Conv3×3 + GN12 + SiLU|171,360|
|融合2|96→64 Conv3×3 + GN8 + SiLU|55,488|
|空间输出|64→4 Conv1×1 + tanh|260|
|FiLM生成|Linear256→320|82,240|
|合计||407,780|

FiLM在两层GN之后、SiLU之前作用，γ/β分别96/64维，缩放/偏置受tanh×0.25限制。输出4张有符号64×64权重图，随输入/参考组合变化。它们不是4个预先标注的主体/背景类别。恒定输入保留关闭局部路径的保护机制。

K=4缓解已知K=2同色区域RGB仿射平面限制，只增加1418总参数；不是已经验证的最优值。64×64仍缺少高分辨率边缘引导，不能保证发丝等细边界，也不能保证肤色不被改变。边缘细化和dense对应后续单独消融。

## 7. 条件颜色生成与渲染

颜色MLP：3→128→128→15，其中15=3×(1全局+4局部)。两层隐藏由z_pair的FiLM调制。

|子项|参数|
|---|---:|
|3→128|512|
|128→128|16,512|
|128→15|1,935|
|FiLM条件头256→512|131,584|
|颜色生成器合计|150,543|
|门控256→4 + sigmoid|1,028|

在17³颜色网格上生成1张全局和4张局部RGB LUT，73,695个动态值。这些值不是额外固定模型参数。全局为identity+受tanh限制的残差，局部单LUT限幅0.15、总体局部上限默认0.15。上述数值均需通过目标拟合上限诊断确认。

默认不使用显式颜色投影。输出为全局查表加4个门控局部查表残差，经输入坐标空间权重融合，再做范围裁切；保留裁切前输出用于越界损失。

原照片不需要与参考同尺寸；编码分支各自缩放224方形，输出查表保留输入栅格大小。输出栅格保持不等于无伪影或已经解决构图敏感性。

## 8. 训练安排与真实可训练规模

|阶段|可训练|冻结|说明|
|---|---:|---:|---|
|heads|5,604,343|85,798,656|冻结MAE，训练所有新增模块|
|joint|33,957,367|57,445,632|再解冻MAE最后4层与最终LN|
|full对照|91,251,703|151,296|固定sin/cos位置仍不更新|

先用已有三元组重建训练heads，再以较小骨干学习率做joint；不增加未经验证的“纯风格解耦”必需损失，不重新训练MAE重建decoder。可选初始学习率：新增头2e-4、joint骨干1e-5，实际需验证，不是既有结果。

独立encoder-only阶段被拒绝，避免冻结零初始化输出头导致无重建梯度。已为完整模型补齐ToneLoss所需global_delta/preclamp_output，测试了真实损失可反向；训练CLI和完整模型训练结果尚未提供。自参考身份等可作为后续独立约束评估。
